# 20260612 Web Frontend UI Redesign

## 배경
중앙 상단의 기존 `TopTabs` 기능을 왼쪽 사이드바로 옮기는 과정에서 프로젝트 목록과 열린 채팅 목록의 역할이 분리되지 않았다.

사이드바의 기존 `Projects`는 `conf.toml`의 `[projects.*]`에 설정된 프로젝트 전체를 표시하고, 프로젝트 탭 상태는 현재 열린 프로젝트 세션을 나타낸다. 새 UI에서는 이 두 정보를 하나의 `Projects` 영역에 결합하되 기존 프로젝트 선택, 복수 프로젝트 세션, 채팅 선택·닫기와 상태 표시 기능을 유지한다.

## 목표
- 중앙 상단은 활성 채팅 제목과 새 채팅 버튼이 있는 단일 `ChatHeader`를 유지한다.
- 왼쪽 사이드바 순서를 `Projects`, `Threads`, 하단 `설정`으로 구성한다.
- `Projects`에 TOML 프로젝트와 열린 프로젝트 세션별 채팅을 함께 표시한다.
- `Threads`는 기존 프로젝트 스레드 목록을 보여주는 단일 접이식 목록으로 단순화한다.
- `Enabled Agents`와 관련 설정 UI를 사이드바 하단 설정 팝오버로 이동한다.
- 오른쪽 Workspace 패널의 기능과 크기 조절은 유지하면서 왼쪽 사이드바와 시각 체계를 통일한다.
- API, SSE, 서버 데이터 형식은 변경하지 않는다.

## 전체 레이아웃
### 중앙 영역
- 기존 `TopTabs`는 제거한다.
- `ChatHeader`에는 활성 채팅 제목과 새 채팅 버튼만 표시한다.
- Composer와 메시지 영역의 기존 동작은 유지한다.

### 왼쪽 사이드바
- 상단의 `Codex Web`, 알림, 테마 헤더는 유지한다.
- 사이드바 접기 버튼은 하단에서 상단 오른쪽으로 이동한다.
- 접기 버튼은 분할 패널 형태의 아이콘으로 교체한다.
- 본문은 카드형 Panel 대신 평면 목록 스타일을 사용한다.
- 섹션 순서는 다음과 같다.
  1. `Projects`
  2. `Threads`
- 하단 왼쪽에는 설정 버튼을 고정한다.

### 오른쪽 Workspace 패널
- 현재 위치, 열기·닫기, 파일 탐색, 미리보기, 새로고침과 너비 조절 기능을 유지한다.
- 배경, 헤더, 행 높이, 간격, hover, 선택 상태와 아이콘 색상을 왼쪽 사이드바 스타일에 맞춘다.
- Workspace 데이터와 파일 트리 동작은 변경하지 않는다.

## Projects
### 데이터 기준
- 기본 목록은 `/api/projects`의 `projectItems`를 사용한다.
- `projectItems`는 `conf.toml`의 `[projects.*]`에 설정된 프로젝트 전체를 의미한다.
- 열린 프로젝트 세션은 `projectTabs`를 사용한다.
- 프로젝트와 열린 세션은 `projectItems.key === projectTabs.key`로 연결한다.
- 세션별 열린 채팅은 `threadTabsByProjectTabId[projectTab.id]`를 사용한다.

### 프로젝트 행 생성 규칙
- 열리지 않은 TOML 프로젝트는 기본 프로젝트 행 하나로 표시한다.
- 프로젝트에 열린 세션이 있으면 기본 행을 열린 세션 행들로 대체한다.
- 동일 프로젝트가 여러 세션으로 열려 있으면 기존 `TopTabs`처럼 동일 프로젝트명의 독립 행을 세션 수만큼 표시한다.
- 별도의 세션 하위 그룹이나 통합 채팅 목록은 만들지 않는다.
- 프로젝트 목록의 기본 순서는 TOML 프로젝트 순서를 유지하고, 동일 프로젝트의 열린 세션은 `projectTabs` 순서를 유지한다.

### 프로젝트 행 동작
- 프로젝트 이름 클릭:
  - 열리지 않은 프로젝트는 기존 `selectProject` 동작을 실행한다.
  - 열린 세션 행은 해당 `projectTabId`를 활성화한다.
- 화살표 버튼:
  - 열린 세션 행에만 표시한다.
  - 해당 세션의 열린 채팅 목록만 접거나 펼친다.
  - 프로젝트 선택 동작과 분리한다.
- 프로젝트 닫기 버튼:
  - 열린 세션 행에만 표시한다.
  - 해당 `projectTabId`의 기존 닫기와 fallback 동작을 실행한다.
- 프로젝트 상태:
  - `projectTabStatusById`의 running, unread, failed, cancelled 상태를 유지한다.

### 펼침 상태
- 최초 렌더 시 활성 프로젝트 세션만 펼친다.
- 이후 각 프로젝트 세션 행의 펼침 상태는 독립적으로 관리한다.
- 여러 프로젝트 세션을 동시에 펼칠 수 있다.
- 펼침 상태는 로컬 UI 상태이며 영구 저장하지 않는다.

### 열린 채팅 행
- 펼친 프로젝트 세션 행 바로 아래에 해당 세션의 열린 채팅을 표시한다.
- 각 행은 flex 구조로 다음 요소를 배치한다.
  - 채팅 선택 영역과 제목
  - running/completed/failed/cancelled/unread 상태
  - 채팅 닫기 버튼
- 채팅을 선택할 때 해당 프로젝트 세션을 먼저 활성화한 후 기존 채팅 조회 동작을 실행한다.
- 채팅 닫기에는 해당 채팅이 속한 `projectTabId`를 명시적으로 사용한다.
- 새 채팅 버튼은 해당 프로젝트 세션을 활성화한 상태에서 기존 생성 동작을 실행한다.

## Threads
- 기존 `Recent / Projects` 서브탭을 제거한다.
- `Threads` 제목 한 줄을 전체 목록의 접기·펼치기 트리거로 사용한다.
- 목록 데이터는 기존 `threadItems`를 사용한다.
- `/api/threads/summaries` 응답 순서와 기존 프로젝트별 조회 동작을 유지한다.
- 프론트엔드에서 신규 최신순 정렬을 수행하지 않는다.
- 열린 채팅과 일치하는 스레드에는 탭의 상태, unread 표시와 닫기 동작을 병합한다.
- 스레드 선택과 새 채팅 생성 동작은 기존 기능을 유지한다.

## 설정 팝오버
- 기존 사이드바의 `Enabled Agents` Panel을 제거한다.
- 다음 요소를 모두 설정 팝오버로 이동한다.
  - Enabled Agents
  - Running Subagents
  - 에이전트 활성화와 비활성화
  - 에이전트별 설정 진입
  - AgentSettingsCard
  - Guardian 설정과 요약
  - 에이전트 설정 오류 표시
- 설정 버튼은 사이드바 하단 왼쪽에 고정한다.
- 팝오버는 사이드바 DOM과 분리된 fixed 레이어로 설정 버튼 위에 표시한다.
- 데스크톱에서는 사이드바의 펼침·접힘 상태를 변경하지 않고 팝오버만 독립적으로 연다.
- 모바일에서는 설정을 열 때 사이드바만 닫고 팝오버는 열린 상태를 유지한다.
- 팝오버 폭은 300px로 고정하되 좁은 viewport에서는 좌우 8px 여백 안으로 줄이고, 긴 내용은 내부 스크롤을 사용한다.
- 설정 버튼 재클릭, 팝오버 바깥 클릭과 `Escape`로 닫는다.
- 기존 설정 저장, 새로고침과 floating guardian 설정 동작은 유지한다.

## 컴포넌트 및 데이터 흐름
- 사이드바 context에 다음 상태를 전달한다.
  - `projectItems`
  - `projectTabs`
  - `activeProjectKey`
  - `activeProjectTabId`
  - `projectTabStatusById`
  - 전체 `threadTabsByProjectTabId`
  - `threadItems`
  - `activeThread`
- 현재 활성 프로젝트의 `threadTabs`만 전달하는 계약은 전체 `threadTabsByProjectTabId` 전달로 확장한다.
- 프로젝트 세션별 채팅 선택·닫기·생성 액션은 `projectTabId`를 받을 수 있도록 명확히 분리한다.
- 상태 계산과 세션 fallback 로직은 기존 domain hook에 유지하고 UI 컴포넌트에서 복제하지 않는다.
- 주요 전달 경로는 다음을 유지한다.
  - `useAppRuntimePresentation`
  - `AppRuntimeContext`
  - `AppSidebarContainer`
  - `AppSidebarPane`
  - `AppSidebarContentPanel`

## 스타일 원칙
- 왼쪽 Projects와 Threads는 배경 카드, 외곽 테두리와 그림자를 제거한다.
- 섹션 제목, 들여쓰기, hover와 선택 상태로 정보 계층을 표현한다.
- 프로젝트 세션과 채팅 상태는 색상만으로 구분하지 않고 기존 상태 표시 요소를 유지한다.
- 채팅 제목은 말줄임 처리하고 선택·닫기 버튼 영역이 줄어들지 않게 한다.
- 오른쪽 Workspace 패널에도 동일한 배경, 행 높이, hover와 선택 색상을 적용한다.
- 모바일 사이드바와 900px 이하 레이아웃의 기존 열기·닫기 동작을 유지한다.

## 검증 전략
### Projects
- TOML 프로젝트가 열리지 않았을 때 기본 행 하나가 표시되는지 확인한다.
- 프로젝트가 열리면 기본 행이 세션 행으로 대체되는지 확인한다.
- 동일 프로젝트의 복수 세션이 독립 행으로 표시되는지 확인한다.
- 각 세션 행에 해당 `projectTabId`의 채팅만 표시되는지 확인한다.
- 활성 프로젝트만 최초 펼침 상태인지 확인한다.
- 프로젝트별 펼침 상태를 독립적으로 변경할 수 있는지 확인한다.
- 프로젝트 이름 선택과 화살표 토글이 서로 간섭하지 않는지 확인한다.
- 비활성 프로젝트 세션의 채팅 선택·닫기가 올바른 `projectTabId`를 사용하는지 확인한다.
- 프로젝트와 채팅의 상태 및 fallback 동작을 확인한다.

### Threads
- `Recent / Projects` 탭이 제거되는지 확인한다.
- 기존 `threadItems`가 단일 접이식 목록에 표시되는지 확인한다.
- 열린 채팅과 일치하는 행에 상태, unread와 닫기 동작이 병합되는지 확인한다.
- 열린 탭이 없는 초기 로드에서도 기존 스레드 목록이 표시되는지 확인한다.

### 설정과 레이아웃
- 설정 팝오버의 버튼, 바깥 클릭과 `Escape` 닫기를 확인한다.
- 접힌 데스크톱 사이드바에서 설정을 열어도 사이드바가 펼쳐지지 않는지 확인한다.
- 모바일에서 설정을 열면 사이드바만 닫히고 팝오버가 유지되는지 확인한다.
- 팝오버가 300px 폭을 사용하고 좁은 viewport 안으로 제한되는지 확인한다.
- 기존 에이전트 활성화, 상세 설정과 저장 동작을 확인한다.
- 사이드바 상단 접기 버튼과 모바일 사이드바 동작을 확인한다.
- 오른쪽 Workspace 패널의 파일 탐색과 너비 조절이 유지되는지 확인한다.
- light/dark 테마와 반응형 레이아웃을 확인한다.

## 완료 기준
- `Projects`가 TOML 프로젝트 전체와 열린 프로젝트 세션별 채팅을 하나의 평면 목록으로 표시한다.
- 동일 프로젝트의 복수 세션과 기존 선택·닫기·fallback 동작이 유지된다.
- `Threads`는 기존 스레드 목록을 표시하는 단일 접이식 영역으로 동작한다.
- 에이전트 관련 UI가 하단 설정 팝오버에서 기존 기능을 유지한다.
- 사이드바 접기 버튼은 상단 오른쪽에서 새 아이콘으로 동작한다.
- Workspace 패널은 크기 조절과 기존 기능을 유지하면서 왼쪽 사이드바와 동일한 시각 체계를 사용한다.
- API/SSE 변경 없이 관련 테스트, 타입 검사, lint와 frontend build가 통과한다.
